\section{What this manual covers}
Every number, table and figure of SOD-ROM v5 and of its supplementary material comes from a Python script in \f{python/\allowbreak{}}.
This manual says which script, how to run it, which random seed it uses, which file holds its output, and how long it takes.
Section~\ref{sec:map} maps the paper to the scripts, section by section. Numbers without a prefix are main-text sections, figures and tables; numbers with the prefix S are in the supplement.
The driver \f{python/\allowbreak{}run\_\allowbreak{}sod\_\allowbreak{}rom\_\allowbreak{}v5.sh} runs everything in the right order.

All results are simulations. Each script is deterministic for a given seed. Re-running it reproduces its stored output file to the printed precision; wall times are the exception.
Run times below are wall-clock on a 2-core Linux machine.

Version 5 rebuilds the paper on free-decay training records. Its new results come from the scripts in \f{python/\allowbreak{}identity/\allowbreak{}} (\f{i1}--\f{i7}). The forced-record, complex-mode, nonlinear and cost results are those of version 4, now mostly in the supplement; their scripts and stored outputs are unchanged. The v3 and v4 manuals and drivers are kept unchanged.

\section{Environment}
\begin{itemize}
\item Computations: Python 3.11 with NumPy 2.4.4, SciPy 1.17.1 and Matplotlib 3.10.9. Nothing else is needed.
\item Cost runs of Section~S10 and the S4 wall times of Section~S8 (\f{c36}, \f{k1}, \f{k2}, \f{n2b}): Python 3.13, NumPy 2.5, SciPy 1.18, on a two-core Intel Xeon at 2.1~GHz, one BLAS thread. These are the wall times the paper prints. Evaluation and step counts do not depend on the machine.
\item The SOD Toolbox (\url{https://github.com/nld-uri/sod-toolbox}), as \f{SOD-toolbox/\allowbreak{}} beside \f{python/\allowbreak{}}. The paper libraries add it to the Python path themselves; nothing needs installing.
\item A \LaTeX\ installation for the figures (\f{text.usetex=True}, Computer Modern). Figure~1 is TikZ, \f{figures/\allowbreak{}tikz/\allowbreak{}fig\_\allowbreak{}c\_\allowbreak{}systems\_\allowbreak{}tikz.tex}, compiled with the paper.
\item Timing runs must run alone, with one BLAS thread (\f{OPENBLAS\_\allowbreak{}NUM\_\allowbreak{}THREADS=1}). The driver does this.
\end{itemize}

\section{Running everything}
\begin{verbatim}
cd python
bash run_sod_rom_v5.sh                  # all stages, about 19.5 h
bash run_sod_rom_v5.sh identity cost    # chosen stages only
bash run_sod_rom_v5.sh figs             # redraw figures and Table S4 from stored outputs
\end{verbatim}
Stages, in order: \f{toolbox} (1~min), \f{ensemble} (7.5~h), \f{geometry} (a few minutes), \f{ic} (0.5~h), \f{mix} (0.3~h), \f{select} (1.5~h), \f{nonlin} (1.5~h), \f{moon} (7.5~h, \f{mb10} included; \f{n14} runs in \f{nonlin}), \f{identity} (about 1~h), \f{cost} (alone; see Section~S10 below), \f{figs}.
\f{identity} needs no output of the other stages.
\f{geometry} needs no output of \f{ensemble}: it regenerates the \f{c18} case-2 records from their seeds.
Within \f{cost}, \f{k1} runs before \f{k2}, which reads its pickles.

To check a re-run, compare each new output file with the stored one (\f{diff}); the stored files are the ones the paper quotes.

\paragraph{Toolbox migration.} The stored outputs of the ensemble and moon-sweep stages were produced before the SOD code moved into the toolbox. \f{test\_\allowbreak{}equivalence.py} checks 28 functions against the original code: identical, or within $10^{-10}$, except \f{gsod}, which forms the covariances before projecting; there the difference is below $10^{-6}$ near the rank cut. After the move the recognition, mode-shape and nonlinear scripts were rerun (\f{c3}, \f{c4}, \f{c6}, \f{c9}, \f{c19}, \f{c20}, \f{c26}, \f{c33}, \f{c35}, \f{n4}, \f{n10}, \f{n11}, \f{n11b}, \f{n13}, \f{mb2}, \f{mb9}); no number the paper prints moved. The geometry and cost scripts (\f{g1}--\f{g3}, \f{c36}, \f{k1}, \f{k2}, \f{n2b}) were written on the toolbox. The long ensemble and moon-sweep stages were not rerun.

\section{Notes}
\begin{itemize}
\item The nonlinear scripts are deterministic; they draw no random numbers.
\item \f{n9\_\allowbreak{}strong\_\allowbreak{}companions.py} without an argument runs the broadband circularity test only; the paper uses the argument \f{0.3} (energy-gated banded rescue).
\item \f{g2} and \f{g3} default to 10 realizations; the paper uses 20, passed as the argument.
\item \f{mb7\_\allowbreak{}amp\_\allowbreak{}compare.py} compares every \f{mb6\_\allowbreak{}*\_\allowbreak{}r*.pkl} it finds. Run after the DMTS sweeps it also lists DMTS and two exploratory bases of an earlier draft (RK, RX), which the paper does not use; \f{mb7\_\allowbreak{}out\_\allowbreak{}v4.txt} is that output. Its rows for the v3 bases equal \f{mb7\_\allowbreak{}out.txt}.
\item \f{i8\_\allowbreak{}interp\_\allowbreak{}check.py} (id) tests whether an SOD basis of a forced record interpolates the transfer function at its SOD frequencies. It does not, and the paper makes no such claim; the script and its outputs are kept for the record.
\item Scripts not listed here belong to earlier drafts or to the identification note. They are kept for the record and are not used by this paper.
\end{itemize}
